# Frontend Performance Budgets

This project enforces bundle budgets via:

```bash
npm run perf:bundle
```

The command runs a production build and validates `dist/assets` sizes using `tools/check-bundle-budget.mjs`.

## Current enforced limits (gzip)

- Largest eager JS chunk: `<= 90KB`
- Initial app-shell JS from the Vite static entry graph: `<= 190KB`
- Largest non-chart lazy JS chunk: `<= 70KB`
- `recharts-vendor-*` chunk: `<= 90KB`
- `victory-vendor-*` chunk: `<= 25KB`
- Initial app-shell CSS from the Vite static entry graph: `<= 25KB`
- `react-vendor-*` chunk: `<= 50KB`
- PWA app-shell precache: `<= 20` entries and `<= 220KB` gzip-equivalent transfer

The startup budget sums every JS and CSS file statically reachable from the Vite entry manifest. Route-level dynamic chunks are governed by the lazy-chunk budgets. The checker also rejects route-warming imports in `src/app/main.tsx`, because those execute at startup while appearing dynamic in the manifest and would otherwise make entry-graph accounting misleading.

The CSS ceiling is a deliberately tight baseline over the verified `~24.5KB` app-shell stylesheet after responsive, offline/error, and accessible-state coverage was added. It leaves approximately `0.5KB` gzip headroom and should not be raised without a measured replacement baseline.

Deferred admin chart code keeps its own explicit vendor budgets instead of relaxing the generic lazy-chunk guardrail for the rest of the app.

## PWA caching scope

The generated service worker precaches only the installable app shell: the HTML entry, its initial JS/CSS graph, favicon, and install icons. Route-level JS/CSS is cached with a stale-while-revalidate policy after the user first visits that route. Large promotional images and every lazy route are intentionally excluded from install-time precaching.

The production service worker imports `public/notifications-sw.js`, so push and notification-click handlers run in the same worker generated by `vite-plugin-pwa`.

If any budget is exceeded, the script exits with non-zero status. The frontend quality workflow runs this production build and budget check as a required CI gate.
